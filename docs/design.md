## 네이티브처럼 보이기 (native-feel)

릴리스 전에 native-feel-skill의 `checklists/ship-readiness.md`(75항목)로 점검한다. 자주 틀리는 것:

- `cursor: pointer` 금지. 버튼·행·탭 모두 기본 화살표 커서.
- 화면 요소(라벨, 버튼 글자, 제목)는 텍스트 선택 안 됨. 입력란과 `.selectable`(커밋 메시지, diff)만 선택 가능.
- 푸시 버튼은 호버 효과 없이 **눌림(`:active`) 상태만**. 목록 행·툴바 아이콘 버튼은 옅은 호버 배경 허용.
- 확인 대화상자는 DOM 모달 대신 OS 다이얼로그(Tauri dialog 플러그인), 알림은 OS 알림.
- 페이지 전환 애니메이션, 짧은 작업의 스켈레톤 로딩 금지. 200ms 넘는 작업에만 로딩 표시.
- 토스트는 macOS 알림 센터처럼 차분하게만 쓴다(`toast.ts`/`Toasts.tsx`): 오른쪽 아래 카드, 왼쪽 종류색 막대 + 아이콘, 제목 한 줄 + 설명 한 줄, 최대 4개. 성공·정보·경고는 4초 뒤 저절로 사라지고 오류는 닫을 때까지 남는다. 긴 오류(git 출력)는 제목 + "자세히" 펼치기로 같은 카드 안에서 보여 주고 별도 배너는 두지 않는다. 들어올 때 슬라이드/페이드 200ms(`--ease`), `prefers-reduced-motion`이면 없음. 종류색은 토큰(`--ok`·`--info`·`--warn`·`--danger`)만. 앱이 백그라운드일 때의 알림은 OS 알림을 쓴다.
- 스크롤은 `behavior: 'smooth'` 금지, OS 스크롤바 그대로.
- 창 그림자·모서리는 OS가 그린다(CSS로 그리지 않음). 창 크기·위치는 다음 실행 때 복원.
- Esc는 항상 무언가를 한다(팝오버 닫기, 작업 취소). 목록은 글자 입력으로 항목 이동.
- 단축키는 OS 관례: macOS `⌘`, Windows/Linux `Ctrl`.

## 한 곳에만 힘주기

이 앱에서 눈에 띄어야 하는 건 **커밋 그래프 하나**다. 그래프는 브랜치별 색과 곡선으로 표현력을 주고,
나머지(툴바, 사이드바, 목록, 다이얼로그)는 조용하고 절제되게 만든다. 장식용 그라데이션, 카드, 배지를 추가하지 않는다.

### 커밋 그래프

- 왼쪽 "브랜치/태그" 열에 ref 칩을 둔다(설명 열 안에 라벨 없음). 칩은 그 커밋 레인 색 테두리 + 옅은 레인 색 채움 + `--fg` 글자(두 테마 대비 확보), HEAD는 더 진한 채움 + 체크 아이콘, 태그는 점선 테두리. 칩에서 노드까지 레인 색 가는 가로선.
- 행 배경은 노드 위치부터 오른쪽으로 레인 색을 `color-mix`로 옅게 틴트(토큰 `--tint`·`--tint-hi`·`--tint-sel` = 기본·호버·선택, 다크가 조금 더 진함). 색 값은 `--graph`에서 파생하고 새 색을 만들지 않는다.
- 노드: 작성자 사진 원형 + 레인 색 링(사진 없으면 이니셜), 머지는 작은 채운 점. 레인 선은 곡선, 굵기 2.5.
- "로컬 변경사항" 행은 점선 원 노드 + HEAD 커밋까지 점선.

### 의미색 (조용하지만 회색 일색은 아니게)

장식이 아니라 **뜻이 있는 곳에만** 상태 토큰 색을 쓴다(GitKraken 참고). 새 색은 만들지 않는다.

- 진행 버튼(스테이지, 메시지 저장 등) `button.go` = `--ok`, 버리기·취소 `button.stop`·`.hunk-danger` = `--danger`, 그 밖의 hunk 버튼은 `--accent`. 옅은 채움(14%) + 같은 색 테두리·글자, 눌림 26%.
- 사이드바 섹션 개수는 강조색 알약(옅은 채움 + 강조색 글자).
- ahead `↑`는 `.up`(`--ok`), behind `↓`는 `.down`(`--info`). 0이면 색 없음.
- 주 버튼(`primary`, 커밋)은 강조색 채움 하나만.
- 뒤로가기 버튼은 어디서나 `button.back`(강조색 글자 + 옅은 강조색 채움, 앞에 ←). 회색 보조 버튼·크게 보기 버튼과 구분된다.
- 크게 보기 버튼은 보라(`--nav-link`) 틴트, 켜진 상태(원래대로·닫기)는 보라 채움 + 흰 글자.
- 선택 상태 `--selected`는 강조색에서 파생(라이트 20%·다크 34%), 탭은 강조색 글자 + 아래 2px 막대.
- PR 종류 라벨·배지: 본문 `accent`, 코멘트 `info`, 승인 `ok`, 변경 요청 `danger`. 안내줄 안 버튼은 안내줄 색을 따른다.
- 강조색 채움 위 글자는 `--on-accent`(흰색), 강조색 틴트 위 글자는 `--accent-fg`(다크는 밝게·라이트는 어둡게). 같은 파랑 글자는 묻힌다.

## 테마 (라이트 / 다크 필수)

- 색은 전부 `ui/src/app/style.css`의 `:root` 토큰으로만 쓴다. 컴포넌트에 색 값을 직접 쓰지 않는다.
- 모드는 `system`(OS 따라감) · `light` · `dark` 세 가지. `<html data-theme="light|dark">`로 강제, 속성이 없으면 OS 설정을 따른다.
- VS Code 웹뷰에서는 "시스템" 모드가 OS가 아니라 VS Code 테마(body의 `vscode-light`·`vscode-dark`·`vscode-high-contrast`)를 따른다(`theme.ts`가 `data-theme`로 반영). VS Code 변수를 쓰지 않고 우리 토큰만 쓴다.
- Canvas처럼 CSS가 안 닿는 곳은 `getComputedStyle`로 토큰을 읽어서 쓰고, 테마가 바뀌면 다시 그린다.
- 중립색은 **Zinc 계열 하나만** 쓴다(따뜻한 회색과 차가운 회색을 섞지 않는다).
- 순수 검정 `#000` 금지. 그렇다고 흔한 `#0B0B0B`/`#111` 대체 검정도 쓰지 않는다.
  다크 배경은 약간 푸른 기가 도는 짙은 회색(`#16181d`)으로, 오래 봐도 눈이 덜 피로하게 한다.
- 강조색은 **하나**이고, 기본은 **OS 강조색**(CSS `AccentColor`, 미지원 웹뷰만 블루 폴백). 사용자가 설정 > 일반에서 고른 프리셋(`theme.ts` `ACCENTS`, 두 테마 모두 읽히는 중간 채도)으로만 바꾼다. 브랜드색을 하드코딩하지 않는다. 그래프 브랜치 색은 예외지만 전부 채도를 낮춰서 두 테마 모두에서 읽혀야 한다.

## 타이포그래피

- 글꼴: **시스템 글꼴 우선**(`-apple-system`, `Segoe UI Variable`). 시스템 글꼴에 한글이 없는 Windows에서만
  번들한 `Pretendard`가 한글을 그린다(맑은 고딕 대신). Inter, Noto Sans KR, Roboto, Arial은 쓰지 않는다.
- 코드·SHA·diff: 시스템 고정폭(`ui-monospace, SF Mono, Menlo, Consolas`).
- 숫자(시간, 개수, 진행률)는 `font-variant-numeric: tabular-nums`.
- 한국어 문장 블록은 `word-break: keep-all`.
- 굵기는 400 / 500 / 600 세 단계로 위계를 만든다.

## 표면 · 테두리 · 그림자

- 기본 테두리는 회색 실선 대신 반투명 토큰(`--border`)을 쓴다.
- 그림자는 진한 검정 대신 배경색 기반의 옅은 그림자(`--shadow`)를 쓴다. 글로우나 네온은 쓰지 않는다.
- 카드는 위계를 나타낼 때만 쓴다.

## 모션

- `linear`, `ease-in-out` 금지. 기본 곡선은 `--ease: cubic-bezier(0.16, 1, 0.3, 1)`.
- 상태 전환은 120–200ms. 스크롤 이벤트로 애니메이션을 돌리지 않는다.

## 아이콘

- Iconify **Solar** 세트만 쓴다(얇고 일정한 선 굵기). 앱이 오프라인에서도 동작해야 하므로 CDN 대신 패키지로 번들한다.
- Lucide 두꺼운 선, FontAwesome, Material Icons는 쓰지 않는다.

## 접근성 기본선

- 키보드 포커스가 항상 보인다(`:focus-visible` 링).
- `prefers-reduced-motion`이면 전환 애니메이션을 끈다.
- 텍스트 대비는 두 테마 모두 WCAG AA 이상.

## 피할 패턴 (흔한 AI 디자인 티)

- 모든 제목 위의 대문자 라벨, 가운데 점(`A · B · C`)으로 이은 메타 문자열, 버튼 끝의 `→`.
- 모든 걸 같은 둥근 카드 + 같은 회색 그림자로 쪼개기.
- 의미 없는 번호 표시(01 / 02 / 03). 실제 순서가 있을 때만 쓴다.

## 문구

- 자연스러운 한국어. "혁신적인", "원활한", "차세대" 같은 상투어는 쓰지 않는다.
- 시스템 용어 대신 사용자 용어: "refspec 설정"보다 "가져올 브랜치".
- 버튼은 무슨 일이 일어나는지 말한다: "Pull", "취소", "변경사항 저장". 버튼과 완료 알림은 같은 단어를 쓴다(Pull → "Pull 완료").
- 오류는 사과하지 않고, 무엇이 잘못됐고 어떻게 고치는지 쓴다.
- 빈 화면은 다음 행동을 안내한다("저장소를 열어 시작하세요").
